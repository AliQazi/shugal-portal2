Integration overview

The Partner API gives approved server-side integrations access to Abid Air’s live public inventory. Inventory remains shared with the Abid Air portal; availability and fares can change between requests.

1. Fetch inventory›2. Select inventoryId›3. Create booking›4. Save reference
One booking endpoint. Submit a group-ticketing or Umrah-package ID as inventoryId. The API identifies its type, calculates the authoritative price, reserves the correct inventory, and returns the new booking’s _id.

Base URL

https://abidairtravels.com/api/external/v1

Authentication

Send the issued API key with every request. Keys must only be stored and used on your server.

Authorization: Bearer aa_live_REPLACE_WITH_YOUR_KEY
Accept: application/json

Alternatively, send X-API-Key: aa_live_…. Available scopes are inventory:read, bookings:read, and bookings:write.

Security: Never place an API key in browser JavaScript, mobile-app source, public repositories, screenshots, or client-visible logs.

Create a unified booking

POST /bookings

First call POST /availability with inventoryId and the Adult, Child, and Infant counts. If available, use the returned five-minute token with the exact same inventory and passenger counts. Each successful booking request reserves inventory.

{ "inventoryId": "65fd12ab34cd56ef7890abcd", "adults": 1, "children": 1, "infants": 0 }
Authorization: Bearer aa_live_REPLACE_WITH_YOUR_KEY
Content-Type: application/json
X-Availability-Token: REPLACE_WITH_AVAILABILITY_TOKEN

Fetch and cancel bookings

List your bookings

GET /bookings?page=1&limit=25

Returns only bookings created by the authenticated API client. Group-ticketing and Umrah-package bookings are combined, sorted newest first, and paginated.

Fetch

GET /bookings/6aa3e6b9a88c2c844c958b54

The API searches the correct booking collection using the booking _id. A client may retrieve only bookings created using its own API key.

Cancel

POST /bookings/6aa3e6b9a88c2c844c958b54/cancel

Only on-hold bookings may be cancelled through the API. Successful cancellation releases the previously reserved seats or package availability. Repeating a completed cancellation returns the already-cancelled booking.

Errors and recovery

{
  "success": false,
  "error": {
    "code": "INSUFFICIENT_INVENTORY",
    "message": "The inventory does not have enough availability."
  }
}
StatusMeaningRecommended action
400Malformed identifier/requestCorrect the request before retrying.
401Missing, invalid, or revoked keyCheck authentication; do not repeatedly retry.
403Missing scope or inactive ownerContact Abid Air integration support.
404Inventory/booking unavailableRefresh inventory or verify the reference.
409Availability/state conflictRefresh state; offer another option.
422Validation failedDisplay field details and correct the payload.
429Rate limit exceededHonor Retry-After; use exponential backoff.
500Unexpected server errorCheck the booking list before deciding whether to retry.

Production checklist

AreaRequirement
CredentialsStore the key in a server-side secret manager or protected environment variable.
Booking IDsPersist the exact booking _id returned by the creation response.
PricingDisplay API-returned selling prices; never submit or calculate authoritative prices locally.
AvailabilityRefresh the selected item immediately before booking and handle HTTP 409.
LoggingLog request IDs, status codes, and references—never API keys or full passport records.
RetriesBack off on 429/5xx responses and verify the booking list before retrying creation.
PrivacyEncrypt passenger data in transit and at rest; restrict access and retention.
Source of truth: The machine-readable OpenAPI contract is distributed alongside this guide as openapi.yaml. Contact Abid Air before relying on undocumented fields.

Support handoff information

When reporting an integration issue, include the timestamp and timezone, endpoint, HTTP status, error code, and returned booking ID. Redact API keys and sensitive passenger data.
